# V5 run notes (102 items, Process side H .. Transducer block)

- Search words (rds label cache + CFIHOS property/equipment-class names, regex on names): temperature, pressure, length, height, time, humidity, density/specific gravity/relative density, accuracy, response/time constant/dead time, rating/pressure class, size/nominal size, thread/NPT, connection, material, coating/finish, certif/approval/explosion/SIL, storage, cleaning/inspection, life, fluid/fill fluid, silicone/PTFE/halocarbon/steel/alloy/aluminium/gold, RTD/thermowell/temperature element, count, transducer.
- rds has no property classes for these items, so rdl matches are uom quantity kinds (length, thermodynamic temperature, pressure, time) as "broad", plus a few NORSOK document classes as "related" (EX certificate, Type approval certificate, Supplier SIL documentation). I used the native rds IRIs and left out the "(PCA RDL concept)" mirrors, which point to data.posccaesar.org IRIs that I did not dereference.
- Hard cases: Reference accuracy / Total performance -> CFIHOS "measuring device accuracy" is an accuracy class, so "related". Specific gravity -> "rated relative density" counted as "exact" (specific gravity = relative density). Temperature limits are ranges, and CFIHOS splits them into lower and upper limits, so "related". Fill fluid -> CFIHOS "fluid name" means the process fluid, so "related". The rds "relative humidity" entry is a Scale (a unit), not the property.
- Values: no material classes exist in rds/CFIHOS for 316 SST, Alloy C-276, carbon or stainless steel, or silicone. Classified: "aluminum" and "gold-plated" to ChEBI elements (related), and "Integral RTD" to Temperature Element / CFIHOS resistance temperature element (broad). Approval, option and two-thing values (for example "Thermowell and RTD") are left unclassified.
- 40 items not_device_property: notes, instructions, order codes, document references, marketing text, starred-offering metadata.
